`acp-go-codex` exposes the local `codex` CLI as an
[Agent Client Protocol](https://agentclientprotocol.com/) agent. It speaks ACP
over [JSON-RPC streams](https://agentclientprotocol.com/protocol/transports),
starts `codex app-server` processes on demand, maps
[ACP prompts](https://agentclientprotocol.com/protocol/prompt-turn) and client
callbacks into Codex app-server requests, and streams
[ACP session updates](/docs/reference/updates) back to the host.

Use it when you want a Codex agent that speaks ACP while keeping Codex protocol
details behind a small Go adapter boundary.

## What it owns

The adapter owns the ACP surface and the lifecycle of the Codex processes it
launches: it translates ACP methods into `codex app-server` requests, streams
the resulting events back as ACP updates, and bridges client callbacks
(permissions, elicitation, MCP) across the boundary. It does **not** own Codex
itself — authentication, model availability, MCP behavior, native telemetry,
and rollout persistence are governed by the installed `codex` CLI version and
the user's Codex configuration. Codex protocol details stay inside the adapter
and never leak onto the ACP wire except through the documented `_codex/*`
extension namespace.
