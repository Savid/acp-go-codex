---
title: "Sessions"
description: "ACP session lifecycle behavior."
---

`session/new` starts a Codex thread. `session/prompt` starts a Codex turn and
streams ACP updates until Codex completes, cancels, or errors.

`session/load` and `session/resume` first check active sessions, then the
configured `SessionStore`, then native Codex thread state.

`session/delete` writes a store tombstone first, closes any active session, and
hides the session from list, load, and resume.

Forking is a Codex extension method named `_codex/session/fork`; the stable ACP
`session/fork` method is not routed.
