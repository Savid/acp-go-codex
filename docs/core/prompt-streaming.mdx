ACP prompt turns are streaming. The final `session/prompt` response carries the
turn stop reason and usage, while intermediate Codex app-server notifications
are mapped to `session/update` notifications.

## Update types

The adapter maps Codex events into portable ACP updates where possible:

| Codex event | ACP update |
| --- | --- |
| Agent text delta | `agent_message_chunk` |
| Reasoning delta | `agent_thought_chunk` |
| Plan update | `plan` |
| Shell command item | `tool_call` / `tool_call_update` |
| File change item | `tool_call` / `tool_call_update` |
| MCP or dynamic tool item | `tool_call` / `tool_call_update` |
| Diff update | tool-call content/update when Codex provides it |
| Account or warning update | `session_info_update` metadata where possible |
| Goal update | `session_info_update._meta.codex.goal` |
| Mode/config change | `current_mode_update` / `config_option_update` |
| Completed turn | final stop reason, `PromptResponse.usage`, and usage update metadata |

When Codex emits only completed items, the mapper emits final text once. When
deltas were already emitted for an item, completed text is treated as final
state without duplicating visible output.

## Content input

ACP prompt content blocks are converted into Codex turn input:

- text blocks become user text;
- URL and data images become Codex image inputs;
- `file://` images become Codex local-image inputs;
- file resource links become Codex mentions;
- non-file resource links and embedded resources become text context.

Unsupported content block types are rejected as invalid params instead of being
dropped.

The adapter serializes turns per session. A second `session/prompt` waits until
the active turn completes or is cancelled.

## Codex command surfaces

Codex-native app-server APIs are exposed as explicit extension methods rather
than as plain text slash commands:

| Extension | Native Codex operation |
| --- | --- |
| `_codex/turn/steer` | `turn/steer` |
| `_codex/thread/compact` | `thread/compact/start` |
| `_codex/review/start` | `review/start` |
| `_codex/thread/read` | `thread/read` |
| `_codex/thread/turns/list` | `thread/turns/list` |

Hosts can still send ordinary text that Codex interprets however the CLI would
interpret it. The extension methods are for app-server operations with typed
inputs and responses.

## Usage

When Codex emits `thread/tokenUsage/updated`, the adapter returns
`tokenUsage.last` as standard ACP `PromptResponse.usage` and also emits a
`usage_update` before the turn is finalized. Codex-native per-turn token
details are preserved under `_meta.codex.usage`; cumulative thread usage, when
reported, is exposed as `usage_update.used`, `usage_update.size`, and
`_meta.codex.threadUsage`.

See [Updates](/docs/reference/updates#usage-updates) for the exact mapping.

Structured output is returned on the final `session/prompt` response under
`_meta.codex.structuredOutput`, not as a streamed update.
