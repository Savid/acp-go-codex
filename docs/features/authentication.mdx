Codex authentication belongs to the Codex CLI and the configured `CODEX_HOME`.
The adapter exposes ACP hooks for hosts that need to start login, provide
external ChatGPT tokens, observe account status, or perform guarded logout.

## Terminal auth

Standalone mode advertises terminal authentication commands. Hosts can run:

```bash
acp-go-codex -cli login
acp-go-codex -cli login -device-auth
```

The command delegates to `codex login` with the same `-codex` and
`-codex-home` settings as the agent process.

## External ChatGPT tokens

Hosts that own ChatGPT auth can call ACP `authenticate` with:

```json
{
  "codex": {
    "auth": {
      "chatgptAuthTokens": {
        "accessToken": "secret",
        "refreshToken": "secret",
        "expiresAt": 1790000000
      }
    }
  }
}
```

Embedded hosts can also provide:

```go
codexacp.WithChatGPTAuthTokenRefresher(func(ctx context.Context) (codex.ChatGPTAuthTokens, error) {
    return tokens, nil
})
```

The refresher handles Codex app-server token refresh callbacks. Tokens are
kept out of response metadata and logs.

## Account status

Codex `account/updated` notifications refresh the session account cache even
when no turn is active. Session responses expose redacted account state under
`_meta.codex.account`.

Access tokens, refresh tokens, raw credential files, and authorization headers
are never emitted.

## Logout

ACP `logout` is guarded. It calls Codex `account/logout` only when the agent is
configured with:

```go
codexacp.WithAllowAccountLogout(true)
```

Leave logout disabled when `CODEX_HOME` points at a user's normal local Codex
credentials. Use it only for adapter-owned homes where the host controls
credential lifecycle.
