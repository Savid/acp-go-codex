Permission flow is a trust boundary. The adapter does not silently approve
Codex requests. Codex owns its native approval and sandbox policy stack; the
adapter preserves the ACP approval boundary and forwards host decisions back to
Codex.

## Configure defaults

| Need | Standalone | Embedded | Per session |
| --- | --- | --- | --- |
| Default approval policy | no dedicated flag | use request metadata defaults in your host | `_meta.codex.options.approvalPolicy` |
| Sandbox policy | no dedicated flag | use request metadata defaults in your host | `_meta.codex.options.sandboxPolicy` |
| MCP tool approval | MCP server metadata | MCP server metadata | per MCP server `Meta` |

Codex policy objects are native Codex shapes. The adapter validates only the
ACP envelope and forwards the policy to `turn/start`.

## Flow

1. Codex emits a server-to-client approval request.
2. The adapter maps the request to ACP `session/request_permission`.
3. The client selects allow, allow for session, reject, or cancel.
4. The adapter submits the corresponding Codex approval decision.
5. Cancellation or connection close detaches pending interactions.

The ACP-facing methods and callbacks are listed in
[ACP methods](/docs/reference/acp-methods).

## Options sent to clients

| ACP choice | Codex decision |
| --- | --- |
| Allow once | `accept` |
| Allow for session | `acceptForSession` |
| Reject once | `decline` |
| Cancel | `cancel` |

The adapter does not keep a separate durable permission store. Any persistence
comes from Codex's own approval cache or from the host's explicit session
metadata on future requests.

## MCP tool approvals

Codex MCP tool approval requests are permission prompts, not generic form
elicitations. When Codex sends an MCP approval request with
`_meta.codex.codex_approval_kind == "mcp_tool_call"`, the adapter routes it
through ACP `session/request_permission`.

Trusted service MCP servers can opt into Codex-native tool approval metadata on
the MCP server definition:

```json
{
  "codex": {
    "defaultToolsApprovalMode": "approve",
    "tools": {
      "execute": {
        "approvalMode": "approve"
      }
    }
  }
}
```

Supported modes are `auto`, `prompt`, and `approve`. This is explicit
per-server trust metadata; `_meta.codex.options.approvalPolicy: "never"` does
not silently approve all MCP tools.

## Cancellation

When `session/cancel` interrupts a turn, outstanding permission requests tied
to that turn are cancelled. Codex receives an interrupt-aware cancel/deny
decision, and the prompt returns `cancelled`.

## File changes

File-change approval and diff events are mapped opportunistically when Codex
emits them. The adapter keeps successful shell output, file updates, and diffs
in the normal prompt stream where possible; raw rollout rows remain available
through [`_codex/sdkMessage`](/docs/features/raw-events) for diagnostics.
