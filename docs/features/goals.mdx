Goals are optional Codex-native thread state exposed through ACP metadata.
Start the adapter with `-enable-goals` or `WithCodexGoals(true)` to advertise
and use the goal surface.

## Shape

Client input uses `_meta.codex.goal`:

```json
{
  "codex": {
    "goal": {
      "objective": "prove 1 + 1 = 2",
      "status": "active",
      "tokenBudget": 50000
    }
  }
}
```

Client-settable fields are `objective`, `status`, and `tokenBudget`. Runtime
fields such as token usage, time usage, timestamps, thread ID, and source are
owned by Codex or the adapter and are returned in response metadata.

## Set Or Clear

Set an initial goal on `session/new`, `session/load`, `session/resume`, or
`session/fork` by including `_meta.codex.goal`.

Clear a goal with:

```json
{
  "codex": {
    "goal": null
  }
}
```

After session start, call `_codex/session/setGoal`:

```json
{
  "sessionId": "session-id",
  "goal": {
    "objective": "prove 1 + 1 = 2",
    "status": "active"
  }
}
```

Use `goal: null` with the same method to clear it.

## Session Lifecycle

Goal state is included under `_meta.codex.goal` on session lifecycle responses
and session info updates. Goal-only updates do not need to be mixed into the
visible message stream.

When a [SessionStore](/docs/features/session-store) is configured, the adapter
can mirror the latest visible goal snapshot to `goal.json` alongside the main
rollout bundle.

## Native Codex Mapping

The adapter maps the ACP goal shape to Codex thread goal APIs. Native
`thread/goal/updated` and `thread/goal/cleared` notifications refresh adapter
metadata even when no prompt turn is active.

Duplicate native notifications that match a direct `_codex/session/setGoal`
response are collapsed into one ACP session info update.

## Privacy

Goals are user-provided session state and may contain sensitive project
information. The adapter treats goal metadata like prompt/session metadata: it
is not logged by default and is emitted only through ACP response/update
metadata or a configured session store.
