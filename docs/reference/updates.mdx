---
title: "Updates"
description: "The ACP session updates and turn-failure error the adapter emits."
---

During a prompt turn the adapter emits ACP `session/update` notifications and,
on completion, resolves `session/prompt` with either a result or a failure
error. For the mental model behind the mapping, see
[Prompt streaming](/docs/core/prompt-streaming).

## Session updates

Codex `app-server` events are mapped to ACP session updates:

| Update category | Source |
| --- | --- |
| `agent_message_chunk` | assistant text |
| `agent_thought_chunk` | reasoning text |
| `plan` | plan changes |
| tool call updates | tool start / output / complete, including diffs |
| tool call image content | image generation and image-view lifecycle |
| usage update | usage events |
| session metadata update | account changes |

Image tools emit complete content snapshots. Successful content uses the
standard ACP image block with sniffed MIME and base64 data. Native failed image
tools emit failed status with no invented content. Adapter-side image
materialization failures emit failed tool status and then fail the turn.

The adapter also emits an identity-bearing session metadata update for the
native turn checkpoint. Its notification metadata contains the native
`_meta.codex.turnId` and, when the turn has a terminal assistant item, the
final `_meta.codex.messageId`. This update is emitted even when the terminal
assistant item has no text. The prompt response carries the same pair.

Raw, unmapped rollout rows are emitted only through
[`_codex/rawEvent`](/docs/features/raw-events) when a session opts in with
`_meta.codex.rawEvent.enabled`.

## Turn failure

A turn that cannot complete resolves `session/prompt` with a JSON-RPC internal
error (code `-32603`) whose `data` object carries the uniform
`codex_turn_failed` contract:

| Field | Description |
| --- | --- |
| `error` | Always `codex_turn_failed`. |
| `cause` | One of `provider`, `timeout`, `process_exit`, `transport`. |
| `message` | Human-readable failure detail. |
| `statusCode` | Provider HTTP status, when the cause is `provider`. |
| `providerCode` | Provider error code, when present. |
| `stage` | `image_output` when the adapter could not represent native image output. |
| `reason` | Image output reason, always `storage_failed`: the other image-output verdicts refuse the tool call without ending the turn. |
| `sizeBytes` | Decoded image or aggregate bytes when known. |
| `maxBytes` | Applied decoded-byte limit when known. |

An auth failure instead resolves with the ACP authentication-required error
(code `-32000`) rather than `codex_turn_failed`.

## Internal errors off the turn path

Every other `-32603` this adapter emits — on `initialize`, a session lifecycle
request, `session/close`, `session/delete`, or an extension method — keeps the
JSON-RPC constant `"Internal error"` as its `message` and carries exactly one
closed token in `data.error`. Nothing else rides `data`: no `message` member, no
Go error text, and no native app-server text.

| Token | Condition |
| --- | --- |
| `codex_invalid_options` | The Agent was built from an option set it will not serve under. `NewAgent` returns no error, so the verdict is delivered on `initialize` and on every session-establishing entry point. |
| `codex_restore_failed` | `session/load` or `session/resume` found a store entry for the session and could not restore it ([Session store](/docs/features/session-store#restoring-on-a-fresh-host)). The entry is neither deleted nor tombstoned. |
| `codex_runtime_unavailable` | The shared app-server is gone and its previous incarnation's process tree is still alive and un-containable ([Sessions](/docs/core/sessions#session-lifecycle)). A runtime that merely exited never produces this token — the next explicit operation replaces it. |
| `codex_internal_failure` | Every failure the adapter cannot classify above. |

The adapter emits no poisoned-session token: a session is never left in a state
that refuses everything but close and delete.
