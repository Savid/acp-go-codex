Session import is a Codex-specific extension surface for restoring durable
rollout JSONL captured outside the local Codex state directory.

`sessionId` is the ACP-visible store key chosen by the host. It can differ from
the native Codex thread ID embedded in the rollout JSONL.

The import format is:

```text
codex-rollout-jsonl
```

Each entry must be one JSON object. The adapter preserves the raw bytes after
validation.

## One-shot import

`_codex/session/import` accepts the same payload as `importChunk`, then commits
the generated import immediately.

```json
{
  "sessionId": "session-id",
  "cwd": "/workspace/project",
  "format": "codex-rollout-jsonl",
  "entries": [
    {"type": "event_msg", "payload": {"type": "agent_message", "message": "hi"}}
  ]
}
```

Response:

```json
{
  "importId": "sess_...",
  "sessionId": "session-id",
  "cwd": "/workspace/project",
  "format": "codex-rollout-jsonl",
  "entries": 1,
  "bytes": 78,
  "sha256": "..."
}
```

## Chunked import

`_codex/session/importChunk` appends entries to a pending import.

Request fields:

| Field | Required | Meaning |
| --- | --- | --- |
| `importId` | no | Existing import ID. If omitted on the first chunk, the adapter generates one. |
| `sessionId` | yes | ACP-visible session/import ID to store. |
| `cwd` | yes | Absolute project directory. |
| `format` | no | Must be `codex-rollout-jsonl` when present. |
| `subpath` | no | Relative store subpath for related rollout artifacts. |
| `offset` | no | Expected entry offset for this subpath. Defaults to `0`. |
| `entries` | no | Array of raw JSON objects. |
| `lines` | no | Array of JSONL strings. |
| `jsonl` | no | JSONL text. Blank lines are ignored. |

At least one normalized entry is required. `entries`, `lines`, and `jsonl` can
be combined.

Chunk response:

```json
{
  "importId": "sess_...",
  "sessionId": "session-id",
  "cwd": "/workspace/project",
  "format": "codex-rollout-jsonl",
  "offset": 100,
  "entries": 100,
  "bytes": 12345
}
```

`offset` is the next expected entry offset for that subpath. The top-level
`entries` count is the total import entry count across all subpaths.

`_codex/session/commitImport` writes the pending import into the configured
`SessionStore`:

```json
{
  "importId": "sess_...",
  "sha256": "optional-expected-hash"
}
```

If `sha256` is present, it must match the import's computed hash. Existing
sessions can be replaced only when the store implements `SessionStoreReplacer`;
otherwise the commit is rejected.

`_codex/session/abortImport` drops a pending import:

```json
{
  "importId": "sess_..."
}
```

Response:

```json
{
  "aborted": true
}
```

## Validation

- Maximum entries per chunk: `10000`.
- Maximum entries per import: `100000`.
- Maximum single JSONL line: `10 MiB`.
- Maximum import byte total: `100 MiB`.
- Pending import TTL: `30 minutes`.
- `cwd` must be absolute.
- `subpath` must be relative and cannot escape the session bundle.

Malformed JSONL, offset mismatches, format mismatches, and stale import IDs are
rejected as invalid params.

## Storage

`subpath: "goal.json"` is reserved for the adapter's latest Codex goal
snapshot. Hosts that export/import full Codex bundles should include this
sidecar when goal restore fidelity matters.

Use `session/load` after import to replay stored rollout rows into ACP updates,
or `session/resume` to restore native Codex context without replay. Both paths
resume the Codex thread from a materialized rollout file. When the rollout
contains `session_meta.payload.id`, the adapter passes that native Codex thread
ID to Codex while keeping the ACP session ID unchanged.
