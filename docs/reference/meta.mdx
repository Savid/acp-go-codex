The adapter reserves the `_meta.codex` namespace for its extension vocabulary.
This page lists what the adapter reads.

## Session options

Accepted session lifecycle metadata:

```json
{
  "_meta": {
    "codex": {
      "options": {
        "model": "gpt-5.5",
        "effort": "high",
        "serviceTier": "flex",
        "personality": "pragmatic",
        "approvalPolicy": "never",
        "sandboxPolicy": "workspace-write",
        "mcpToolApprovalMode": "approve",
        "outputSchema": {"type": "object"}
      },
      "rawEvent": {
        "enabled": true
      }
    }
  }
}
```

## Initialize capabilities

Accepted initialize capability metadata under `_meta.codex`:

| Key | Purpose |
| --- | --- |
| `fork` | `_codex/session/fork` extension method. |
| `elicitation` | Client capability gated elicitation support. |
| `rawEvent` | `_codex/rawEvent` notification opt-in details. |
| `sessionStore` | Store format and key shape. |
| `structuredOutput` | JSON Schema request and response paths. |

## Rules

Unknown keys in the adapter-owned namespace fail closed with invalid params.
Wrong-typed values for known option keys are also rejected with invalid params
whose data is `{"error": "unsupported", "field": "_meta.codex.options.<key>"}`
— never silently ignored. There is no command capability or command metadata
under `_meta.codex`.

Skills surfaces (`skills/list`, `$skill`, `type:"skill"` items) are not commands
and are not projected as `AvailableCommand` entries.
