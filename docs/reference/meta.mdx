The adapter reserves the `_meta.codex` namespace for its extension vocabulary,
and reads and writes a small set of `acp-go.dev/*` keys that are not
vendor-specific. This page lists the metadata it reads and writes.

## Session options

Accepted session lifecycle metadata:

```json
{
  "_meta": {
    "codex": {
      "options": {
        "model": "gpt-5.5",
        "effort": "high",
        "serviceTier": "flex",
        "personality": "pragmatic",
        "approvalPolicy": "never",
        "sandboxPolicy": "workspace-write",
        "mcpToolApprovalMode": "approve",
        "outputSchema": {"type": "object"}
      },
      "rawEvent": {
        "enabled": true
      }
    }
  }
}
```

## Initialize capabilities

Accepted initialize capability metadata under `_meta.codex`:

| Key | Purpose |
| --- | --- |
| `fork` | `_codex/session/fork` extension method. |
| `elicitation` | Client capability gated elicitation support. |
| `rawEvent` | `_codex/rawEvent` notification opt-in details. |
| `sessionStore` | Store format and key shape. |
| `structuredOutput` | JSON Schema request and response paths. |

## Media envelope

Every initialize response advertises the bounds this adapter enforces on inbound
prompt media, under the reserved `acp-go.dev/mediaEnvelope` key in
`agentCapabilities._meta`. A host reads it to reject an oversize or unsupported
attachment before it spends a turn on one:

```json
{
  "agentCapabilities": {
    "_meta": {
      "acp-go.dev/mediaEnvelope": {
        "maxBytes": 6291456,
        "maxPromptBytes": 6291456,
        "maxDimension": 0,
        "imageFormats": ["image/png", "image/jpeg", "image/gif", "image/webp"],
        "documentFormats": []
      }
    }
  }
}
```

| Field | Meaning |
| --- | --- |
| `maxBytes` | Effective decoded bound on one prompt image — [`ImageLimits.MaxInputBytesPerImage`](/docs/reference/go-api#agent-options). |
| `maxPromptBytes` | Effective decoded bound on every image in one prompt — `ImageLimits.MaxInputBytesPerPrompt`. |
| `maxDimension` | Per-dimension pixel bound. Always `0`: Codex reads dimensions only to prove they exist and rejects nothing for being large in pixels. |
| `imageFormats` | The inbound allowlist, in this order. |
| `documentFormats` | Media types mapped to a native document representation. Always an empty array: Codex has none, so a host should materialize documents rather than embedding their bytes. |

The block is always present. Its byte values track the configured
`WithImageLimits`, so they are the values the gates actually enforce rather than
a documented approximation; `0` on a byte field means that adapter policy limit
is disabled, and `0` on `maxDimension` means no bound rather than no pixels.

The envelope is captured per agent instance, so it expresses only bounds the
adapter enforces. It cannot express whether the session's currently selected
model accepts images, which stays a prompt-time result
([`unsupported_by_model`](/docs/core/prompt-streaming)).

## Handoff advertisement

When — and only when — [`WithInputHandoffRoot`](/docs/reference/go-api#agent-options)
is configured, initialize also advertises the local handoff input transport:

```json
{
  "agentCapabilities": {
    "_meta": {
      "acp-go.dev/handoff": {"versions": [1]}
    }
  }
}
```

The key's absence is the actionable signal that no handoff root reached this
adapter, so a host can check its own configuration rather than discovering the
gap on a rejected prompt. The inbound envelope a host sends per block is
documented with the [handoff input form](/docs/core/prompt-streaming).

## Rules

Unknown keys in the adapter-owned namespace fail closed with invalid params.
Wrong-typed values for known option keys are also rejected with invalid params
whose data is `{"error": "unsupported", "field": "_meta.codex.options.<key>"}`
— never silently ignored. There is no command capability or command metadata
under `_meta.codex`.

Skills surfaces (`skills/list`, `$skill`, `type:"skill"` items) are not commands
and are not projected as `AvailableCommand` entries.

## Native turn identity

Successful native turns expose their durable Codex correlation under
`_meta.codex` on a standard `session/update` notification and on the terminal
`session/prompt` response:

```json
{
  "_meta": {
    "codex": {
      "turnId": "<native turn id>",
      "messageId": "<final assistant response-item id>"
    }
  }
}
```

`turnId` comes from the Codex app-server turn. `messageId`, when present, is
the final assistant `response_item.id` from that turn; it is not an
adapter-generated ACP message id. A completion with no assistant item carries
`turnId` alone. Store-backed `session/load` replays the same terminal identity
from the mirrored rollout.
