The adapter routes the standard ACP method set and adds namespaced
`_codex/*` extensions. This page lists each method and its behavior.

## Supported methods

| Method | Status |
| --- | --- |
| `initialize` | implemented |
| `session/new` | implemented |
| `session/prompt` | implemented |
| `session/cancel` | implemented |
| `session/close` | implemented |
| `session/list` | implemented |
| `session/load` | implemented |
| `session/resume` | implemented |
| `session/delete` | implemented |
| `session/set_config_option` | implemented |

For `mode`, `effort`, and `personality`, select-option lists are rendering
menus rather than local allowlists. Any nonempty value is stored as the current
value and reaches the next native turn; Codex's acceptance, rejection, or
fallback is authoritative. Empty values, the boolean variant, and unknown
`configId` values are still rejected as input-shape errors. A native verdict
does not arrive for all three: an unrecognised `mode` or `personality` fails the
next turn with Codex's own text, while an `effort` is accepted whatever it says,
so a value Codex cannot use surfaces during the turn or not at all.

`session/prompt` and active-turn `session/cancel` require the exact version-1
`acp-go.dev/route` metadata described in [Sessions](/docs/core/sessions#turn-route-identity).
Missing and stale turn nonces are invalid params; there is no unstamped path.
The exact refusal shapes are in [`_meta` reference](/docs/reference/meta#turn-route).

`session/new`, `session/load`, `session/resume`, and `_codex/session/fork`
require an absolute `cwd`, and `session/list` requires one for its optional
filter. A relative or empty value is invalid params carrying
`{"error": "unsupported", "field": "cwd"}` before any native process or store
entry exists. A `_codex/*` request whose params cannot be decoded, or do not
validate as a whole, is invalid params carrying
`{"error": "unsupported", "field": "params"}`.

## Extensions and unsupported methods

Codex extension methods live under the `_codex/*` namespace:

| Method | Status |
| --- | --- |
| `_codex/session/fork` | implemented through `HandleExtensionMethod` |
| `_codex/rateLimits` | implemented through `HandleExtensionMethod` |
| `_codex/rawEvent` | notification only |
| `_codex/auth/methods` | implemented through `HandleExtensionMethod` |
| `_codex/auth/authorize` | implemented through `HandleExtensionMethod` |
| `_codex/auth/callback` | implemented through `HandleExtensionMethod` |
| `_codex/auth/status` | implemented through `HandleExtensionMethod` |
| `_codex/auth/cancel` | implemented through `HandleExtensionMethod` |
| `_codex/auth/inventory` | implemented through `HandleExtensionMethod` |
| `_codex/auth/credential` | implemented through `HandleExtensionMethod`, consent-gated |
| `_codex/auth/disconnect` | implemented through `HandleExtensionMethod`, consent-gated |

The eight `_codex/auth/*` legs broker a ChatGPT or API-key login for the
account `CODEX_HOME` holds. They are advertised together under
`agentCapabilities._meta.codex.providerAuth` only while `-provider-auth-root`
is configured, and `credential` and `disconnect` additionally require
`-provider-auth-direct-home` equal to `-home`; every unadvertised leg returns
method-not-found (see [Authentication](/docs/features/authentication)).

Unsupported or removed methods return method-not-found uniformly. `session/fork`
and `session/set_mode` are intentionally not routed.

### `_codex/rateLimits`

`_codex/rateLimits` reads fresh quota observations for an effective provider.
Params may include opaque, nonblank `providerId` and `sessionId` strings. An
addressed session supplies its effective provider configuration; without one,
the native app-server configuration resolves the provider. A missing selector
that cannot resolve a provider fails with `missing` / `providerId`. Malformed,
unknown, duplicate, or wrongly typed fields fail with invalid params.

```json
{
  "providerId": "openai",
  "availability": "available",
  "pools": [
    {
      "id": "codex",
      "planType": "pro",
      "windows": [
        {
          "id": "primary",
          "usedPercent": 18,
          "durationSeconds": 604800,
          "observedAt": "2026-09-08T04:43:55Z",
          "resetsAt": "2026-09-15T00:00:00Z"
        }
      ]
    }
  ]
}
```

The native ChatGPT account reader supports the built-in `openai` provider.
The native account's authentication mode determines eligibility; an ambient
API-key variable does not override a ChatGPT account reported by Codex. Codex's
resolved default ChatGPT endpoint is supported.
Unknown providers, API-key authentication, and custom endpoints or provider
authentication are `unsupported`. A logged-out account is `unavailable` with
reason `not_authenticated`; failed reads use `read_failed`, and absent or
expired observations use `not_observed`. These responses always contain
`pools: []`. Session lookup and lifecycle errors remain protocol errors.

Every request uses the Agent's shared app-server and makes a bounded native
read without a prompt or model turn. A provider-wide request can start that
runtime without creating a session. The adapter checks native configuration
and account identity around the read and discards observations if the account,
authentication, runtime, or addressed session changes. Caller cancellation
cancels the read. The complete read has a 30-second bound and no result cache.

Each native allowance remains a separate pool; pool labels and plan types are
included when reported. Window IDs retain the native `primary` / `secondary`
identity, while `durationSeconds` reports the actual measured duration.
`usedPercent` preserves measured zero and values above 100. `observedAt` is the
UTC native-response receipt time; reset-expired windows are omitted. Unknown
facts remain absent, and window status is not inferred from percentages.
Codex credit counters and spend-control fields do not identify a currency, so
they do not become monetary balances.

## Slash commands

acp-go-codex advertises no ACP slash commands. `/review`, `/plan`, `/compact`,
and other slash-prefixed text remains ordinary `session/prompt` text and reaches
Codex as `turn/start` input.

Skills surfaces (`skills/list`, `$skill`, `type:"skill"` items) are not commands
and are not projected as `AvailableCommand` entries.
