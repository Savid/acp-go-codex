---
title: "Security"
description: "Native execution and filesystem trust boundaries."
---

Omitting `WithHostAuthority` runs Codex as the adapter's current user. On Linux,
the ordinary launcher retains only process-group guardianship and a writable-home
lock outside prepared trees.

An embedded host selects managed execution with `WithHostAuthority`. The host
supplies the native environment, prepares every tree before Codex can read it,
starts each native process, revokes the runtime lease, waits for terminal proof,
and reclaims each tree. A nil or unusable supplied authority fails before a tree
is changed or a process is launched.

The shared app-server belongs to the Agent. Session cancel and close use only
thread protocol operations and never revoke that shared process. Runtime
retirement fences new admission, shuts down the protocol, calls `Revoke` and
`Wait`, and only then reclaims and removes retired rollout and prompt-input
residences. Count and byte bounds force retirement before another residence is
admitted.

Managed executable selectors must be configured for host pinning. The adapter
refuses session-created `node_modules` Codex copies with guidance to stage and
pin the executable before initialization.
