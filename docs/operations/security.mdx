Treat rollout rows, raw event rows, MCP payloads, diffs, terminal output, and
app-server request/response bodies as sensitive.

## Permission prompts

Permission flow is load-bearing. Do not bypass ACP `session/request_permission`
unless the active Codex policy explicitly does so. The adapter does not keep a
separate durable permission store; any persistence comes from Codex's own
approval cache or explicit host metadata on future session requests.

MCP tool approvals are routed through the same permission boundary when Codex
marks the request as an MCP tool call approval.

## Codex authentication

Codex CLI authentication state is owned by Codex and the selected `CODEX_HOME`.
The adapter does not parse, redact, edit, or delete Codex credential files
directly. It uses Codex `account/*` app-server APIs or the `-cli login/logout`
passthrough.

[Standalone CLI and embedded Go](/docs/get-started/run-modes) share this
boundary. `-codex-home` and `WithCodexHome` only choose which Codex home is
passed to the Codex process.

Only enable ACP logout with `WithAllowAccountLogout(true)` when `CODEX_HOME`
points at an adapter-owned credential directory.

## External auth

[External ChatGPT token auth](/docs/features/authentication#external-chatgpt-tokens)
accepts `chatgptAuthTokens` under `_meta.codex.auth`. Tokens are passed to
Codex account APIs or returned from the embedded refresher callback. Tokens are
kept out of response metadata and logs.

Redacted account metadata may include non-token account fields such as account
ID, email, and plan type. Do not treat it as anonymous data.

## MCP bridge token files

[ACP-transport MCP](/docs/features/mcp#acp-transport-bridge) uses a loopback
listener and a local stdio proxy. The bridge token is written to a `0600` temp
file under a private `0700` parent directory so the token value does not appear
in argv or env values.

Normal close removes the token file. `SIGKILL` can orphan it in `$TMPDIR`.
Deployments should keep OS temp cleanup enabled, such as `systemd-tmpfiles` or
an equivalent boot/session sweep for stale `acp-go-codex-mcp-token-*` files.

Plain streamable HTTP MCP header values are passed through Codex
`env_http_headers`, with generated environment variables injected into the
Codex process. Header values are not placed in argv, but the same-user process
boundary still applies: a same-user process that can inspect process
environments may see them.

## Filesystem boundaries

- `cwd` must be absolute.
- `additionalDirectories` must be absolute.
- Codex home is configured with `-codex-home` in standalone CLI or
  `WithCodexHome` in embedded Go and is treated as trusted local
  configuration.
- [Session store](/docs/features/session-store) materialization writes an
  isolated temp rollout file under a private temp directory and removes it on
  close.

## Logging and telemetry

Do not log credentials, MCP bridge tokens, prompt text, tool input/output, raw
Codex JSON, rollout rows, diffs, or goal objective text unless the host
deliberately opts into that data path. See
[Observability](/docs/operations/observability#privacy-defaults),
[Goals](/docs/features/goals#privacy), and
[Raw Events](/docs/features/raw-events) for explicit data paths.

Native Codex OTEL mapping never writes OTEL header values into Codex `-c`
arguments because those arguments are visible to same-user process inspection.
If standard OTEL header variables are present, they remain environment values
under the same same-user process boundary described above.
