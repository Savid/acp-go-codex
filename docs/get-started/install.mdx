## Install standalone CLI

Install the ACP subprocess:

```bash
go install github.com/savid/acp-go-codex/cmd/acp-go-codex@latest
```

Then configure your ACP host to launch `acp-go-codex` over stdio. The agent
starts `codex app-server` processes for sessions on demand.

## Install embedded Go

Add the package to a Go module:

```bash
go get github.com/savid/acp-go-codex
```

Call [`Serve`](/docs/reference/go-api#serve) when your application already owns
the ACP input and output streams:

```go
err := codexacp.Serve(ctx, input, output,
    codexacp.WithCodexPath("/usr/local/bin/codex"),
    codexacp.WithCodexHome("/var/lib/my-host/codex"),
)
```

## Codex discovery

The adapter finds Codex in this order:

1. `-codex <path>` in standalone mode or `WithCodexPath(path)` in embedded Go.
2. `codex` from `PATH`.

Use a pinned CLI path when your host needs reproducible app-server behavior.

## Codex configuration

Use `-codex-home <dir>` or `WithCodexHome(path)` to set `CODEX_HOME` for
launched Codex processes. Leave it empty to use the user's default Codex home.

For service-owned deployments, prefer an adapter-owned `CODEX_HOME` with
explicit auth and cleanup policy. For user-owned editor integrations, avoid
destructive account operations unless the user requested them.

## Authentication commands

The standalone binary can pass through local Codex auth commands:

```bash
acp-go-codex -cli login
acp-go-codex -cli login -device-auth
acp-go-codex -cli logout
```

`logout` through ACP is guarded separately by
[`WithAllowAccountLogout`](/docs/reference/go-api#auth).

## Environment

Common environment variables:

| Variable | Purpose |
| --- | --- |
| `CODEX_HOME` | Used by Codex when no `-codex-home` or `WithCodexHome` override is set. |
| `OTEL_*` | Configures standalone adapter telemetry and native Codex OTEL mapping. |
| `CODEX_OTEL_ENVIRONMENT` | Sets the native Codex `otel.environment` tag. |

<Warning>
  Do not use OpenTelemetry console exporters in ACP stdio mode. Console
  exporters write to stdout, which is also the JSON-RPC transport.
</Warning>
