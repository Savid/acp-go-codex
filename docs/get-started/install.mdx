## Install the CLI

Install the standalone ACP agent binary:

```sh
go install github.com/savid/acp-go-codex/cmd/acp-go-codex@latest
```

For embedded use, add the package to your module:

```sh
go get github.com/savid/acp-go-codex
```

```go
err := codexacp.Serve(ctx, stdin, stdout,
	codexacp.WithExecutablePath("/usr/local/bin/codex"),
	codexacp.WithHome("/var/lib/my-host/codex"),
)
```

## Point at Codex

The adapter launches the local `codex` CLI on demand. Select which executable
and home it uses:

| Setting | CLI flag | Go option |
| --- | --- | --- |
| Codex executable | `-path` | `WithExecutablePath` |
| Codex home (`CODEX_HOME`) | `-home` | `WithHome` |

When `-path` is unset the adapter resolves `codex` from `PATH`. When `-home` is
unset each launched Codex process uses the operator's default Codex home.

## Authenticate

Authentication is owned by Codex, not the adapter. Log in through the terminal
helpers, which delegate to `codex`:

```sh
acp-go-codex login -codex-device-auth
acp-go-codex logout
```

ACP logout is refused unless the adapter is started with
`-codex-allow-account-logout` or `WithCodexAllowAccountLogout(true)`, so a
misbehaving client can never clear the credentials of an operator-owned Codex
home. See [Authentication](/docs/features/authentication) for the full flow.
